> 生成器模式用于创建“步骤多、组合多”的复杂对象，将构造过程拆分并独立管理，使得创建对象的方式更灵活、更可扩展、更易读、更好维护。

## 一、为什么会有生成器模式？（背景故事）

想象你在开发一个 **“点餐系统”**。

用户可以点一份汉堡套餐，而套餐可能包含：

- 主食：牛肉汉堡 / 鸡肉汉堡 / 素汉堡
- 饮料：可乐 / 雪碧 / 咖啡
- 小食：薯条 / 鸡块
- 可选：加芝士、双层肉、不要洋葱……

用户组合可能非常多，如果直接用构造函数：

```
new Meal("牛肉汉堡", "可乐", "薯条", true, false, true, ...)
```

不仅难读，而且未来套餐内容一多，构造函数会“爆炸式增长”。

为了避免这种复杂对象的创建变成噩梦，**生成器模式应运而生**。

---

## 二、生成器模式解决的核心问题

生成器模式主要用于：

> **构建一个“包含很多步骤或组合”的复杂对象时，让构建过程清晰、有条理、可控制、可扩展。**

它的精髓在于：

- 把“对象怎么一步步建造”独立出来
- 把“最终生成的对象”与“生成过程”分离
- 调用者可以自由组合构建步骤
- 同一个构建过程可以生成不同产品

简单说就是一句话：

> **把复杂对象的创建过程拆散，变成可控的“积木式构造”。**

---

## 三、生成器模式的结构

典型的生成器模式包含：

1. **Product（产品）**：要被构建的复杂对象
2. **Builder（抽象Builder）**：定义构建步骤（如设置主食、饮料等）
3. **ConcreteBuilder（具体Builder）**：实现每一步该怎么造
4. **Director（指挥者，可选）**：按特定顺序调用构建步骤
5. **Client（使用者）**：告诉 Director 要什么产品

---

## 四、一个简单示例：建造“套餐 Meal”

### 🍔 Product（产品）

```java
class Meal {
    String burger;
    String drink;
    String snack;

    @Override
    public String toString() {
        return "Meal: " + burger + ", " + drink + ", " + snack;
    }
}

```

---

### 🧱 Builder（抽象建造者）

```java
interface MealBuilder {
    void buildBurger();
    void buildDrink();
    void buildSnack();
    Meal getMeal();
}

```

---

### 🏗 ConcreteBuilder（具体建造者）

例如：**牛肉汉堡套餐建造者**

```java
class BeefMealBuilder implements MealBuilder {
    private Meal meal = new Meal();

    @Override
    public void buildBurger() { meal.burger = "牛肉汉堡"; }

    @Override
    public void buildDrink() { meal.drink = "可乐"; }

    @Override
    public void buildSnack() { meal.snack = "薯条"; }

    @Override
    public Meal getMeal() { return meal; }
}
```

---

### 📋 Director（指挥者）

```java
class MealDirector {
    public Meal createMeal(MealBuilder builder) {
        builder.buildBurger();
        builder.buildDrink();
        builder.buildSnack();
        return builder.getMeal();
    }
}
```

---

### 👤 Client（使用者）

```java
public class Main {
    public static void main(String[] args) {
        MealDirector director = new MealDirector();
        MealBuilder builder = new BeefMealBuilder();

        Meal meal = director.createMeal(builder);
        System.out.println(meal);
    }
}

```

输出：

`Meal: 牛肉汉堡, 可乐, 薯条`

---

## 五、生成器模式的好处

### ✔ 1. 构造过程清晰，步骤可控

按步骤构建，不会产生超长构造函数。

### ✔ 2. 创建逻辑与产品本身分离

Meal 是对象，MealBuilder 是构造方法，职责清晰。

### ✔ 3. 同样的构建步骤可以生产不同产品

换个 Builder 就能生成鸡肉套餐、素食套餐，但步骤一样。

### ✔ 4. 可以自由组合构建步骤

想省略饮料？想加两个汉堡？Builder 允许灵活改造。

### ✔ 5. 扩展性极强

新增一种套餐，只需新增一个 Builder，不需要改原代码。

---

## 六、什么时候该用生成器模式？

适用场景非常明确：

### ✔ **构造函数包含很多参数（尤其是可选参数）**

例如：

```java
new User(name, age, phone, email, address, vipLevel, loginCount, ...)
```

### ✔ **对象的构建过程有明确步骤，需要顺序控制**

如搭建房子、制作套餐、生成复杂 JSON/XML 等。

### ✔ **同样的构建步骤，可以生产不同版本产品**

如不同类型的电脑、汽车、Protocol 消息等等。

### ✔ **需要让构造过程更灵活、可阅读、可扩展**

比起巨大的构造函数，Builder 更易维护。
